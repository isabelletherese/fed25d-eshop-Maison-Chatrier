## 01: Day 1 setup

**Owner:** Catalog   **User stories:** Shared setup   **Blocked by:** nothing

### What to build

Give all three roles a shared database and storefront layout so they can build and verify their parts of the shop. Catalog owns the ticket and all three roles contribute.

### Acceptance criteria

- [ ] Apply `db/setup.sql` to create the ER tables with row-level security enabled and no browser policies, and load the launch test data with six garments across the three categories and at least one sold-out size.
- [ ] The app can query the database through `lib/db.ts`. A teammate can identify the required configuration from `.env.example`, including the test customer credentials, with no actual secrets in the example.
- [ ] Open the app in the browser and see the shared Maison Chatrier layout.
- [ ] One Vitest 3 integration test fetches the app through its normal page URL and checks the status and shared layout. Vitest loads configuration through Vite’s `loadEnv`.

### Done when

- [ ] Every criterion passes, checked by hand, and the tests and the build pass.
- [ ] Run the Vitest integration test against the dev server and observe it fail when the covered behavior is temporarily broken. Restore the behavior and verify the test passes.
- [ ] Record the output of `npm test`, `npm run build`, and `npm run lint`, and explain how to verify the ticket in the browser.
